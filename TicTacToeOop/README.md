# Игра "Крестики-нолики" на принципе ООП
## Задача
Была поставлена задача разработать игру "Крестики-нолики", используя ООП. 
При этом программа должна остаться легко переносимой на другие платформы.
## Принцип работы
В процессе рефакторинга программы я пользовался следующими принципами:
- Класс не знает о платформе (только логика)
- Каждый метод или функция класса выполняет свою определённую задачу
- Избегание процедурного кода вне Program.Main()\
Использовал метод композиции (Класс Game содержит классы Board, Player).\
## Принятые решения
Были выделены пять классов: Program, Player, Board, Game, ConsoleUI.\
`Program` - связующий узел, знающий о платформе, являющийся процедурным по своей сути.\
`Player` - содержит информацию об имени и знаке (крестик/нолик) игрока, а также вычисляет количество всех 
созданных игроков с возможностью очищения.\
`Board` - владеет двумерным массивом состояний ячеек (enum CellStates), а также методами и функциями: 
проверка возможности хода, совершение хода, проверка на три знака в ряд, проверка всего поля на заполненность, 
передача копии массива состояний ячеек.\
`Game` - содержит экземплярные поля, методы и функции, владеет "правилами ведения" игры. Создаёт доску, 
двух игроков и через поля определяет текущего игрока, победителя и окончание игры. "Процесс" игры решено перенести в 
Program.RunGame().\
`ConsoleUI` - класс, обладающий статическими методами, выводящими данные в консоль (использовал для отрисовки меню, 
доски, правил игры.
## Как запустить
Запуск программы производится через EXE-файл, находящийся в каталоге Releases на странице репозитория.
## Заключение
Задача решена успешно. Функционал игры полностью сохранён, а также обеспечена переносимость на другие платформы.\
